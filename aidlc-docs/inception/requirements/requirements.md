## 技術スタック（決定事項）

| 領域 | 技術 | 根拠 |
|---|---|---|
| フロントエンド | Next.js 14+ / TypeScript | App Router、SSR/SSG、Vercelとの親和性。薄いUIレイヤーに徹する |
| スタイリング | Tailwind CSS | 開発速度とカスタマイズ性 |
| バックエンド | Python / FastAPI | AI処理・ビジネスロジックを集約。anthropic SDK との親和性、マルチモデル対応 |
| データベース | PostgreSQL（Supabase） | リレーショナルデータ、リアルタイムサブスクリプション |
| 認証 | Supabase Auth | JWT発行。FastAPI側でJWT検証（python-jose） |
| AIモデル | Vertex AI（Google Cloud） | Louge生成・知恵洗浄。Cloud Run と同一GCPプロジェクト内で IAM 認証。モデルは Gemini 系を基本とし切り替え容易 |
| ファイルストレージ | Supabase Storage | 将来的な添付ファイル対応 |
| デプロイ（フロントエンド） | Vercel | Next.js ホスティング |
| デプロイ（バックエンド） | Google Cloud Run | FastAPI コンテナ実行。サーバーレス・スケーラブル。GCP AIサービス（Vertex AI等）との親和性 |
| 状態管理 | Jotai | アトミックな状態管理、シンプルなAPI |
| サーバー状態 | React Query (TanStack Query) | FastAPI エンドポイントへのフェッチ・キャッシュ・非同期処理 |

## 機能要件

### FR-01: ユーザー管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-01-1 | メールアドレス＋パスワードによるユーザー登録・ログイン | Must |
| FR-01-2 | Googleソーシャルログイン | Should |
| FR-01-3 | ユーザープロフィール画面（アバター、自己紹介、所属業種） | Must |
| FR-01-4 | インサイト・スコア、獲得バッジをプロフィールに表示 | Must |
| FR-01-5 | 非ログインユーザーはSeed一覧・Louge閲覧のみ可（投稿不可） | Must |

### FR-02: Seed（種）— 問いの投下

| ID | 要件 | 優先度 |
|---|---|---|
| FR-02-1 | 8タイプのSeed投稿：疑問(Query)・悩み(Pain)・失敗(Failure)・仮説(Hypothesis)・比較(Comparison)・違和感(Observation)・シェア(Knowledge)・実践報告(Practice) | Must |
| FR-02-2 | タイプに応じたステップ型入力フォーム（タイプ選択→ガイド付き入力） | Must |
| FR-02-3 | タグ付け機能（業種・テーマカテゴリ） | Must |
| FR-02-4 | AIによるリアルタイム知恵洗浄（社名・個人名の検知と抽象化提案） | Should |
| FR-02-5 | Seed一覧フィード（成長ステージでフィルタ可能、非ログイン閲覧可） | Must |
| FR-02-6 | Seed詳細ページ（内容・成長ステージ・Log一覧表示） | Must |
| FR-02-7 | ForkされたSeedは親LougeへのリンクをSeed詳細に表示 | Must |

### FR-03: 成長ステージ（植物モデル）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-03-1 | 6段階ステージをUIで可視化：Seed → Sprout1 → Sprout2 → Sprout3 → Louge → Harvest | Must |
| FR-03-2 | Log数・参加者数・多様性スコアに基づく自動ステージ進行 | Must |
| FR-03-3 | 開花基準（Log数、参加者数、多様性）の設定値をシステムで管理 | Must |
| FR-03-4 | 開花基準に近づいたSeedへの参加促進通知 | Should |

### FR-04: Log（水やり）— 対話・コメント

| ID | 要件 | 優先度 |
|---|---|---|
| FR-04-1 | Seedに対するLog（コメント）投稿（ログインユーザーのみ） | Must |
| FR-04-2 | Logへの返信（スレッド構造） | Should |
| FR-04-3 | Logへのリアクション（共感・役立った等） | Could |

| FR-04-5 | 各ユーザーのLog投稿数・貢献履歴の記録 | Must |

### FR-05: Louge（開花）— AI知識記事生成

| ID | 要件 | 優先度 |
|---|---|---|

| FR-05-3 | Louge一覧ページ（タグ・カテゴリフィルタ、検索） | Must |
| FR-05-4 | Lougeのステータス管理（生成中・公開・アーカイブ） | Must |

## 非機能要件

### NFR-01: パフォーマンス
- フィードページの初期表示: 3秒以内
- Louge生成（AI処理）: ユーザーへの処理中表示あり、バックグラウンド非同期実行
- API応答時間: 通常操作で500ms以内

### NFR-02: スケーラビリティ
- 初期フェーズ: 〜1,000 DAU（日次アクティブユーザー）を想定
- Supabase無料枠〜プロプラン範囲での運用

### NFR-03: ユーザビリティ
- レスポンシブデザイン（モバイル・デスクトップ対応）
- 日本語UI（初期）
- Seed成長状態の直感的な植物ビジュアル表現

### NFR-04: 信頼性・可用性
- Vercel / Supabase のSLAに依存
- AI処理失敗時のエラーハンドリングとリトライ機構

### NFR-05: セキュリティ
- セキュリティ拡張（SECURITY-01〜15）はスキップ（PoC/プロトタイプ段階）
- 基本的な認証・認可は Supabase Auth に委任
- 環境変数でシークレット管理（ハードコード禁止）

### NFR-06: 保守性
- TypeScript strict モード
- ESLint / Prettier による統一コーディングスタイル
- コンポーネント単位のテスト（Vitest / Testing Library）

## ユーザーペルソナ

### Seeker（課題解決を求める実務担当者）
- 現場の悩みを持つビジネスパーソン（人事・マーケター等）
- 検索では見つからない「他社の泥臭い実例」を求める
- プライマリアクション: Seed投稿、Louge閲覧

### Contributor（価値証明を求めるプロフェッショナル）
- 実務経験を持つ専門家
- スキルを「会社の所有物」でなく個人資産として可視化したい
- プライマリアクション: Log投稿、インサイト・スコア獲得
