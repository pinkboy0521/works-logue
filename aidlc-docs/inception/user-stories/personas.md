# Works Logue — ペルソナ定義

## ペルソナ 1: Seeker（課題解決者）

### 基本プロフィール

| 項目 | 内容 |
|---|---|
| **名前** | 田中 美咲（Misaki Tanaka） |
| **年齢** | 34歳 |
| **職種** | 人事マネージャー |
| **所属** | 中規模メーカー（社員数500名） |
| **技術リテラシー** | 中程度（業務SaaSは使いこなせる、開発経験なし） |

### 目標（Goals）
- 組織の採用・定着課題を解決するための「他社の実例」を得たい
- 「正解のない問い」に対して、現場経験者の生の声を集めたい
- 自社内で解決できない課題に対して、外部知見でブレイクスルーを起こしたい

### ペイン（Pains）
- 検索すると出てくるのは「理想論」ばかりで泥臭い実例が見つからない
- コンサルタントや書籍の知識は高コストで抽象的すぎる
- 業界内の知人ネットワークに頼るしかなく、視野が狭くなる
- 問いをさらす「恥ずかしさ」があり、悩みを公に出しにくい

### ゲイン（Gains）
- 自分の課題が類似する状況で解決されたケースを発見できる
- 匿名性・業種抽象化で安全に悩みを投稿できる
- Lougeという形でまとまった知識として消化できる
- 貢献してくれた人々への感謝と連帯感を感じられる

### 行動特性
- スマートフォンで通勤中・昼休みに閲覧
- Seed投稿は「本当に困ったとき」に行動する動機付けが必要
- Louge（知識記事）をブックマークして後から見返す
- Log（コメント）を書くより読む側が多い（Lurker傾向）

### 利用シーン
1. **情報収集フェーズ**: Louge一覧を検索し、類似課題の解決策を閲覧
2. **課題投稿フェーズ**: 「疑問(Query)」や「悩み(Pain)」タイプでSeedを投稿
3. **成長観察フェーズ**: 自分のSeedにLogが集まる様子をウォッチする
4. **再播種フェーズ**: 解決策を実践してForkでフィードバックを返す

## ペルソナ 2: Contributor（価値証明者）

### 基本プロフィール

| 項目 | 内容 |
|---|---|
| **名前** | 鈴木 健太（Kenta Suzuki） |
| **年齢** | 41歳 |
| **職種** | フリーランス / 組織開発コンサルタント |
| **所属** | 独立（前職：大手HR企業10年） |
| **技術リテラシー** | 高め（Web活用に慣れている、ノーコードツール経験あり） |

### 目標（Goals）
- 自分の実務経験・知見を「会社の所有物」ではなく個人資産として可視化したい
- 市場価値の証明につながる「スキルの実績」を積み上げたい
- 自分が貢献した知識が、実際に誰かの課題解決に役立ったことを確認したい

### ペイン（Pains）
- LinkedInのプロフィールでは「何をやったか」しか見せられない
- 講演・登壇は機会が少なく、貢献の場が限られている
- 知見を発信しても反響がわかりにくく、モチベーションが続かない
- 「貢献した知識がLougeになった」という達成感を感じる場がない

### ゲイン（Gains）
- インサイト・スコアとバッジで貢献の「量と質」が可視化される
- 開花貢献者として名前が記録され、Lougeに永続的に紐づく
- 他者のSeedに応答することで自分の知識を整理・深化できる
- 同じ専門分野のコミュニティと繋がる機会が生まれる

### 行動特性
- PCブラウザで時間をかけてじっくりLogを書く（質重視）
- 自分の専門領域に関連するSeedを検索・フィルタして探す
- インサイト・スコアやバッジをモチベーションに継続投稿
- Logの返信（スレッド）で深い議論を好む

### 利用シーン
1. **探索フェーズ**: タグ・業種でフィルタして回答できそうなSeedを探す
2. **Log投稿フェーズ**: 実務経験をもとにLog（水やり）を投稿する
3. **貢献確認フェーズ**: 自分のLogへのリアクション・Louge化を確認する
4. **スコア確認フェーズ**: プロフィールのインサイト・スコア・バッジを確認する
